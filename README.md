# llama.cpp Windows Manager (ext)

Менеджер локальных LLM (llama.cpp) для Windows: загрузил модель, покрутил параметры,
**установил службой — и забыл**. Служба сама поднимает постоянный шлюз локальных моделей,
переживает перезагрузки и не зависит от того, что происходит в графическом интерфейсе.

> **Происхождение:** это форк [llama.cpp Windows Manager](https://github.com/alekk89/llama-cpp-windows-manager)
> (автор **alekk89**, лицензия **MIT**), распространяемый **as is** — без каких-либо
> гарантий. Копирайт-уведомление оригинала сохранено в файле [LICENSE](LICENSE)
> без изменений. Данный README описывает изменения форка относительно оригинала.
>
> **Протестировано на:** Intel Core i9-14900K, 96 ГБ ОЗУ, NVIDIA GeForce RTX 5090
> (32 ГБ VRAM), модель **Qwen 3.6 35B** (`Qwen3.6-35B-A3B-UD-IQ4_NL.gguf`).

## Главное отличие форка

**Служба `llama-cpp-server` — постоянный шлюз локальных LLM.**

Классический сценарий:

1. Загрузил модель (Hugging Face или вручную в `data/models`).
2. Настроил профиль запуска (контекст, GPU-слои, кэш, температура...).
3. На странице «Управление службой» выбрал модель, профиль и среду выполнения.
4. Нажал «Установить службу» и «Запустить службу».
5. **Забыл.** После перезагрузки Windows служба сама поднимает шлюз и модель.

Служба полностью автономна: при старте она сама читает из БД приложения выбор
(модель/профиль/среда) и параметры запуска, строит аргументы `llama-server` и
форсирует правила шлюза. Никакие действия в GUI (случайная перезапись конфига,
закрытие окна) не могут сломать запуск службы.

## Возможности

- **Единый шлюз локальных моделей** — порт из настроек приложения («Порт шлюза»,
  по умолчанию `8101`); доступ в LAN — по настройке «Доступность в LAN».
- **Простое имя модели для API** — `--alias` формируется из имени файла
  (`-`/`_` → пробел): `Qwen3.6-35B-A3B-UD-IQ4_NL.gguf` отдаётся как
  `Qwen3.6 35B A3B UD IQ4 NL` — никаких хешей и «сырых» путей.
- **Автономная Windows-служба** — переживает перезагрузки, запускается до GUI,
  не зависит от него.
- **GUI не конфликтует со службой** — при работающей службе приложение не поднимает
  свой шлюз, показывает модель службы как загруженную; кнопки «Загрузить»/«Unload»
  и селекторы блокируются.
- **Журнал в реальном времени** — служба пишет вывод `llama-server` в
  `data/logs/llama-server-*.log`; страница «Обзор» показывает его вживую.
- **Обновления с этого форка** — проверка обновлений смотрит на
  [репозиторий MRafStudio](https://github.com/MRafStudio/llama-cpp-windows-manager),
  а не на оригинал.
- Прочее (из оригинала): модели Hugging Face, профили запуска, группы и компаньоны
  (vision/draft/MTP), локальный управляющий API и `llwmctl` (см. [docs/CONTROL_API.md](docs/CONTROL_API.md)),
  безопасное хранение данных в `data/`.

## Установка

Два способа (оба включены в релиз):

1. **Portable** — распаковать архив, запустить `LlamaCppWindowsManager.exe`.
   Каталог `data/` (модели, среды выполнения, состояние) создаётся рядом при
   первом запуске.
2. **Инсталлер** (Inno Setup) — `LlamaCppWindowsManager-Setup-<версия>-win-x64.exe`;
   при обновлениях `data/` пользователя сохраняется.

## Быстрый старт

1. Запусти приложение.
2. Загрузи модель (страница «Модели») или положи GGUF в `data/models` и добавь папку.
3. Убедись, что среда выполнения (llama-server) установлена (страница «Среды выполнения»).
4. Открой страницу «Управление службой»: выбери модель, профиль и среду,
   нажми «Установить службу», затем «Запустить службу».
5. Готово: единый шлюз работает по адресу `http://127.0.0.1:<порт шлюза>`.

Подробнее о службе: [docs/LLAMAMANAGER-SERVICE.md](docs/LLAMAMANAGER-SERVICE.md).

## Служба вкратце

- Установка/удаление: `LocalLlmConsole.Service.exe --install` / `--uninstall`
  (из каталога приложения, от администратора) — или кнопки на странице
  «Управление службой».
- Выбор (модель/профиль/среда) хранится в `data/state/service-config.json`
  (пишет страница «Управление службой»).
- Параметры запуска — из профиля в БД приложения; настройки шлюза
  (порт/LAN/автозагрузка) — из «Настроек».
- При старте без выбора служба честно падает с понятной ошибкой в журнале
  Windows (никаких фоллбэков на «левую» модель).

## Подключение клиентов

Любой OpenAI-совместимый клиент — например, конфиг Hermes:

```yaml
providers:
  llama:
    base_url: http://127.0.0.1:8101/v1
    model: Qwen3.6 35B A3B UD IQ4 NL
```
