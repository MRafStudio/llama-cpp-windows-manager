## Что такое служба llama-cpp-server

Это Windows-служба, которая запускает `llama-server` как **постоянный шлюз локальных LLM**:

- **Порт шлюза — из настроек** — служба слушает порт «Порт шлюза» приложения
  («Автозагрузка шлюза» включена; по умолчанию `8101`). Если автозагрузка шлюза
  отключена — модель запускается на порту своего профиля, как при прямом запуске.
- **Доступ в LAN — из настроек** — «Доступность в LAN»: при режимах
  «Шлюз в LAN»/«Шлюз и прямые модели в LAN» служба слушает `0.0.0.0`, иначе —
  только `127.0.0.1`.
- **Простой alias для API** — шлюз отдаёт имя модели через `--alias`, сформированное
  из имени файла: разделители `-` и `_` заменяются на пробелы.
  Например, `Qwen3.6-35B-A3B-UD-IQ4_NL.gguf` отдаётся как `Qwen3.6 35B A3B UD IQ4 NL`.
  Никаких хешей и «сырых» имён файлов.
- **Полная автономность** — при запуске служба сама читает:
  - выбор (модель / профиль запуска / среда выполнения) — из `data/state/service-config.json`
    (файл пишет страница «Управление службой» приложения);
  - параметры запуска (контекст, слои GPU, параллелизм, кэш, температура и т.д.) —
    из профиля в БД приложения (`data/state/local-llm-console.db`);
  - настройки доступа (порт шлюза, LAN, автозагрузка шлюза) — оттуда же.
  Аргументы для `llama-server` служба строит **сама**. Действия в GUI (включая
  случайную перезапись файла конфигурации) не могут сломать запуск службы.
- **Журнал в реальном времени** — вывод `llama-server` пишется службой в
  `data/logs/llama-server-<timestamp>.log`; страница «Обзор» показывает его
  в окне «Журнал среды выполнения в реальном времени».
- **GUI не конфликтует со службой** — если служба запущена, приложение не поднимает
  собственный шлюз, показывает модель службы как загруженную, кнопка «Загрузить»,
  «Unload» и селекторы модель/профиль блокируются.

## Установка службы

Служба устанавливается своим же исполняемым файлом (нужны права администратора):

```cmd
D:\LlamaManager\LocalLlmConsole.Service.exe --install
```

После установки служба `llama-cpp-server` настроена на автозапуск
(`start= auto`) и поднимется после перезагрузки Windows.

Удаление службы:

```cmd
D:\LlamaManager\LocalLlmConsole.Service.exe --uninstall
```

(`--uninstall` сам останавливает и удаляет службу.)

> Служба самодостаточна (self-contained) — установленный .NET не требуется.
> `data/` ищется рядом с exe службы (тот же каталог, где лежит приложение).

## Настройка: что и как грузить

1. Скопируйте GGUF-модели в `data\models\` и зарегистрируйте их в приложении
   (страница «Модели» → «Добавить папку»).
2. Откройте страницу **«Управление службой»** и выберите:
   - **модель** (из каталога),
   - **профиль запуска** (параметры: контекст, GPU, кэш, температура...),
   - **среду выполнения** (llama-server: скачивается на странице «Среды выполнения»).
3. Запустите службу (кнопка на странице или `sc start llama-cpp-server`).

Выбор сохраняется в `data/state/service-config.json` (только идентификаторы —
модель/профиль/среда). Изменили параметры профиля? Они применятся при следующем
запуске службы.

## Ошибки при старте (честные, без фоллбэков)

Если служба не стартует, проверьте Windows Event Log — там будет понятное сообщение:

| Ситуация | Сообщение |
|---|---|
| Нет файла конфигурации | «Конфигурация службы не найдена... Откройте страницу „Управление службой“...» |
| Не выбрана модель | «В конфигурации службы не выбрана модель...» |
| Модель не найдена в БД | «Модель '...' не найдена в базе данных приложения...» |
| Нет профиля | «Профиль запуска '...' не найден в базе данных...» |
| Нет среды выполнения | «llama-server не найден (среда выполнения '...')...» |

Служба намеренно **не подставляет** модель/параметры «по умолчанию» — левая модель
или левые параметры опасны для агента. Лучше честная ошибка и явный выбор.

## Взаимодействие с Hermes-агентом

Hermes (или любая OpenAI-совместимая программа) подключается к шлюзу:

```text
base_url: http://127.0.0.1:8101/v1
model:    Qwen3.6 35B A3B UD IQ4 NL   (как отдаёт /v1/models)
```

`/v1/models` возвращает модель под красивым именем (alias) — без хешей и путей.
